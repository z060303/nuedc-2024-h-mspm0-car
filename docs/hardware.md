# 硬件连接与联调

本表取自 [`24_H.syscfg`](../24_H.syscfg) 和实际电机控制代码。控制器为 **MSPM0G3507 LQFP-64(PM)**，原工程 `targetConfigs/MSPM0G3507.ccxml` 选择 **J-Link**。具体开发板、310 电机驱动器型号和电源电压未在工程里写明，因此接线前应核对所用模块的实物丝印与数据手册。

| 功能 | MCU 引脚 / 外设 | 代码状态 |
| --- | --- | --- |
| 维特 HWT101 SDA / SCL | PA0 / PA1，I²C0 | 地址 `0x50`，读取角度 |
| 灰度模块 RX / TX | PB5 / PB4，UART1，115200 | MCU PB5 接模块 TX；MCU PB4 接模块 RX |
| 左电机 PWM | PA8，TIMA0 CCP0 | 软件限制命令绝对值 `≤350` |
| 左电机方向 | PB8 / PB6 | 正命令：PB8=1、PB6=0；负命令相反 |
| 右电机 PWM | PA7，TIMA0 CCP1 | 软件限制命令绝对值 `≤350` |
| 右电机方向 | PB23 / PB27 | 正命令：PB23=1、PB27=0；负命令相反 |
| 一组编码器 QEI | PB15 / PB22 | SysConfig 已分配，应用尚未读取计数 |
| 模式键 / 启动键 | PA24 / PA25 | 上拉输入，按下为低电平；仅待机时扫描 |
| 声音相关 GPIO | PA9 | 已配置，主动鸣叫代码未启用 |
| 原 OLED I²C | PB3 / PB2，I²C1 | `.syscfg` 仍保留引脚配置；公开版本无 OLED 驱动 |
| 调试 SWD | PA20 / PA19 | 按实际仿真器与开发板接口核对 |

原工程的两只电机据用户说明为 **310 编码器电机**。MCU 引脚不能直接驱动电机，左右 PWM 与方向信号需要进入合适的电机驱动器，电机供电来自适配该驱动器与电机的电源。MCU、灰度模块、HWT101 和电机驱动器信号地应共地；各模块供电电压、电平兼容性、保护与电流容量需依据实物确认。本仓库没有电机驱动器型号、接线照片或实测电源记录，不能推断驱动器端子名或电池规格。

HWT101 的 I²C 读取使用 7 位地址 `0x50`；若模块仍处于其他接口模式或地址被更改，程序会读不到角度。安装后先静止观察 `yaw` 的变化，再低速转动车体核对偏航角正负方向。

## 推荐联调顺序

1. **只接 MCU 与传感器**：运行 SysConfig 生成的固件，确认 HWT101 通信成功，灰度模块通过 UART1 发来以 `$D` 开头、`#` 结尾的报文。不要根据 OLED 显示验证公开版本，因为显示模块已移除。
2. **核对任务键**：PA24 切换模式、PA25 启动；默认模式为任务 4。按键按下为低电平，启动后按键扫描暂停。首次试车应把车轮架空并准备断电。
3. **单独测电机方向**：先只连接一侧电机驱动，使用很小的 PWM 命令确认正负命令对应的转向；另一侧重复。源码允许负命令，正式赛题前须确保车辆运动符合只能前进的要求。
4. **检查灰度权重**：把黑线依次放在传感器左、中、右侧，观察原始 8 位数据与 `gray_error`，确认差速能让车回到线附近。`sensor_status` 的 `0/1` 物理含义取决于灰度模块配置。
5. **逐项验证路径**：从任务 1 开始，记录 `line_exist`、`cross_point_cnt`、`yaw`、左右 PWM、实际运行时间和停车位置，再调整阈值与 PID。未经实测不能把边沿计数直接解释为 A/B/C/D 点。

当前 `QEI_0` 只分配了一组输入引脚。要使用两个编码器做双轮速度闭环，还需为另一只编码器配置可用输入资源，并验证每转计数、计数方向及采样周期。不要把“电机带编码器”误认为固件已经实现了编码器反馈。
